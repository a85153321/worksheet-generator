# Word 範本設計規範

本文件記錄 `src/services/reference-template-docx.ts` **目前已實作、實際會執行**的範本契約。適用範圍是 `public/templates/生字學習單注音版.docx` 與 `reference-character-practice` 匯出流程。

> 重要：目前不是通用的 `{{placeholder}}` 範本引擎。範本後續題目雖然可看見 `{{character}}`、`{{radical}}`、`{{strokeCount}}`、`{{zhuyin}}` 等文字，現行程式不會解析或替換它們。程式只取第一題的固定段落，替換其中的特定字面值，再複製該段落產生所有題目。

## 一、現行範本的整體辨識方式

程式開啟 DOCX（ZIP）後，直接修改下列 OOXML 檔案：

- `word/document.xml`
- `word/_rels/document.xml.rels`
- `[Content_Types].xml`

它不使用 Word 書籤、內容控制項、欄位、圖片檔名或替代文字來找位置。本文中的 `<w:p>` 會依出現順序整理成陣列，然後用固定索引取用：

| 段落索引（從 0 起） | 現行用途 |
| --- | --- |
| `0` | 文件標題，原樣保留 |
| `1` | 班級、座號、姓名列，原樣保留 |
| `2` | 第一題完整題目母版；所有題目都由此段落複製 |
| `3`～`6` | 第一題後方的四個空白／間隔段落；每題都會複製 |
| `7` | 語詞候選列母版；程式在段落結尾附加語詞 |
| `32` | 每 5 題插入一次的分頁段落，必須含手動分頁 `<w:br w:type="page"/>` |

現行程式另有「本文段落至少 63 個」的檢查。少於 63 個便視為範本結構不符；但超過 63 個不代表新增的內容會被使用。除上述索引及最後的 `<w:sectPr>` 頁面設定外，原範本的其他題目段落不會進入輸出文件。

第一題母版（索引 `2`）目前是一個 Word 群組繪圖，外層仍掛在一個本文段落上；群組內含多個巢狀段落與文字方塊。程式會掃描這個完整外層段落內的所有 `<w:t>`，所以群組內的文字也會被替換。

## 二、文字標記規則

### 2.1 生字

在第一題母版段落內，把每個需要顯示生字的位置放入一個內容**恰好等於 `看`** 的 `<w:t>` 節點：

```xml
<w:t>看</w:t>
```

程式會把第一題母版內所有完全等於 `看` 的文字節點替換成當題生字。這包括大字、描寫格、題目資訊列的生字及「讀音」位置所用的字。

若匯出字型不是 `standard-kai`，程式會先依生字與選定注音解析 IVS，輸出「生字 + Unicode variation selector」。範本內採用「ㄅ字嗨注音而已 R」的那些位置，會藉由字型及 IVS 顯示注音；程式**不會**另外把 `item.zhuyin` 寫入一個注音文字節點。若匯出字型是 `standard-kai`，則只寫一般生字，不附 IVS。

限制：凡是第一題母版內單獨出現且內容為 `看` 的節點都會被替換。因此不要在說明文字或裝飾文字中放置另一個獨立的 `看`。

### 2.2 部首

每個需要顯示部首的位置，必須是一個內容**恰好等於 `目`** 的 `<w:t>` 節點：

```xml
<w:t>目</w:t>
```

所有完全等於 `目` 的節點都會替換成 `item.radical`；無部首資料時顯示 `—`。

### 2.3 筆畫數

需要顯示筆畫數的位置，必須是一個內容**恰好等於 `9`** 的 `<w:t>` 節點：

```xml
<w:t>9</w:t>
```

所有完全等於 `9` 的節點都會替換成 `item.strokeCount`；無資料時顯示 `—`。

### 2.4 題號

題號不是獨立標記。程式尋找第一題母版內「包含 `第 1 題`」的 `<w:t>` 節點，再只替換其中這段文字。例如：

```xml
<w:t>第 1 題：【</w:t>
```

會依題序成為 `第 2 題：【`、`第 3 題：【` 等。`第`、`1`、`題` 若被 Word 拆成不同 `<w:t>`，就不會匹配。

### 2.5 注音

目前沒有 `{{zhuyin}}` 或其他「直接寫入注音字串」的有效標記。現行方法如下：

1. 在要呈現注音字形的位置放置生字標記 `看`。
2. 該文字 run 使用支援這套 IVS 的注音字型；目前範本使用「ㄅ字嗨注音而已 R」。
3. 程式依 `item.character` 與 `item.zhuyin` 呼叫 `resolveBopomofoDisplayCharacter`。
4. 能解析時輸出「生字 + IVS」，由字型決定畫面；不能解析時只輸出生字。

因此，範本中打入 `{{zhuyin}}` 不會被替換。新電腦若未安裝對應字型，顯示結果也可能不同。

### 2.6 語詞候選

語詞候選**沒有佔位文字**。程式固定取段落索引 `7`，在該段落的第一個 `</w:p>` 前新增一個 run：

- 字型：`標楷體`
- 字級：`w:sz="20"`，即 10 pt
- 內容：前三個 `wordCandidates`，以 `、` 連接
- 無語詞時：`________________、________________`

索引 `7` 內既有的「【常用語詞造詞參考】：」會原樣保留。不要用 `{{words}}` 取代它；現行程式不認得該標記。

## 三、圖片規則

### 3.1 圖片如何被選中

圖片來自當次 `WorksheetDoc.images`，程式以 `image.character` 建立對照表，再用當題的 `item.character` 找圖片。也就是說：

- 不是依範本內圖片檔名辨識。
- 不是依範本內圖片順序辨識。
- 不是依圖片的替代文字、標題或 shape 名稱辨識。
- 現行範本本身不需要放一張等待替換的示意圖片。

目前參考範本的 DOCX 內沒有 `word/media/*` 圖片，也沒有 image relationship；第一題的圖形是 Word 群組繪圖，不是待替換的點陣圖片。

### 3.2 圖片如何插入

找到當題圖片後，程式會：

1. 以圖片的 URL 讀取二進位資料。
2. 新增為 `word/media/reference-{題號}.{副檔名}`。
3. 在 `word/_rels/document.xml.rels` 新增 image relationship。
4. 在第一題母版段落的結尾插入一個新的 DrawingML 浮動圖片。

插入位置完全由程式寫死，沒有範本標記：

| 屬性 | 現行值 |
| --- | --- |
| 水平基準 | `column` |
| 水平位移 | `5,700,000` EMU |
| 垂直基準 | `paragraph` |
| 垂直位移 | `920,000` EMU |
| 寬 | `1,000,000` EMU，約 2.78 cm |
| 高 | `760,000` EMU，約 2.11 cm |
| 文繞圖 | `wrapSquare` |
| 可重疊 | 是 |

所以新範本目前**無法靠放置一張命名圖片來標記位置**。若仍沿用現行程式，新範本必須讓第一題母版段落與頁面／欄位幾何維持相容，否則固定座標的圖片會偏移。若要自由配置圖片位置，必須先改程式，加入真正的圖片佔位機制。

## 四、Word 編輯注意事項

### 4.1 標記不可被拆成多個 XML 文字節點

`看`、`目`、`9` 必須各自完整存在於單一 `<w:t>`；`第 1 題` 必須連續存在於同一個 `<w:t>`。下列結構無法匹配題號：

```xml
<w:r><w:t>第 </w:t></w:r>
<w:r><w:t>1</w:t></w:r>
<w:r><w:t> 題</w:t></w:r>
```

Word 可能因局部格式、不同字型、拼字校正、輸入法、自動校正、追蹤修訂、貼上內容、欄位或書籤邊界而拆分 run。製作完成後應解壓 DOCX，直接檢查 `word/document.xml`，不要只用 Word 畫面判斷。

### 4.2 不要改變固定段落順序

- 不要在標題之前、標題與姓名列之間、姓名列與第一題之間新增或刪除本文段落。
- 第一題母版必須保持在索引 `2`。
- 第一題後必須保留索引 `3`～`6` 的四個間隔段落。
- 語詞列必須保持在索引 `7`。
- 手動分頁段落必須保持在索引 `32`。
- 本文直接段落總數至少要有 63 個。

「本文直接段落」是 `w:body` 中最外層的 `<w:p>`。表格儲存格內的段落並不會成為上述固定索引；但第一題外層段落內群組物件的巢狀文字仍會隨母版段落一起被掃描。

### 4.3 避免會改寫 OOXML 的功能

- 關閉追蹤修訂，並接受或拒絕所有既有修訂後再交付範本。
- 移除批註、拼字／文法標記及不必要的內容控制項。
- 不要把標記做成 Word 欄位、公式、SmartArt、WordArt 或圖片中的文字。
- 不要在標記的單一字串中混用字型、粗體、字色或其他局部格式。
- 關閉會自動替換輸入內容的自動校正選項，輸入後再以 XML 驗證實際文字。
- 儲存為標準 `.docx`，不要儲存成舊式 `.doc` 或啟用巨集的 `.docm`。

### 4.4 樣式與識別的關係

程式只替換 `<w:t>` 文字，原 run 的字型、字級、顏色、定位與圖形格式會保留。因此同一個 `看` 可在不同位置使用不同樣式。但樣式本身不是識別條件：只要節點內容完全等於 `看`，不論字型為何都會被替換。

所有題目都由第一題母版複製；修改範本中第二題到第五題的外觀，不會改變實際輸出。

## 五、目前是否支援多份範本

目前不支援任意多版型直接上傳使用，原因包括：

- 範本 URL 寫死為 `templates/生字學習單注音版.docx`。
- UI 與匯出路由只有一個 `reference-character-practice` 模板 ID。
- 每頁固定 5 題。
- 段落索引、字面標記及圖片座標全部寫死。
- 沒有範本清單、版本、上傳、驗證或每份範本的設定資料。

底層 `createReferenceTemplateDocxBuffer(templateBytes, doc, options)` 可以接收不同的 DOCX bytes，但只有在新檔案完全遵守本文件的同一份結構契約時才可能工作；這不等於支援不同版型。

### 5.1 僅增加「同結構、不同外觀」範本

若每份範本都保留相同段落索引、第一題群組結構、字面標記、每頁題數和圖片座標，調整範圍較小：

1. 把固定 URL 改為由模板設定傳入。
2. 建立模板 ID、名稱、檔案 URL 的 registry。
3. 在模板選擇 UI 與匯出路由傳遞所選模板 ID。
4. 為每份檔案加入結構驗證與匯出測試。

### 5.2 支援「結構與版面都不同」範本

這需要中型重構，建議先完成再設計任意新版型：

1. 定義正式的範本 descriptor：模板 ID、檔案、每頁題數、重複區塊、圖片尺寸及定位等。
2. 改用唯一且明確的標記，例如 Word 內容控制項的 tag，或可跨 run 合併解析的 `{{character}}` 類標記。
3. 為重複題目區塊建立明確邊界，不再依 `paragraphs[2]`、`paragraphs[7]`、`paragraphs[32]`。
4. 為圖片建立真正的圖片內容控制項或明確關聯標記，不再依固定座標盲插。
5. 增加上傳、保存、選擇、版本管理與錯誤訊息。
6. 補上每份範本的結構驗證、快照／XML 測試及 Word 實際開啟驗證。

以下標記可作為未來設計方向，但**目前尚未實作，現在放入範本不會生效**：

```text
{{questionNumber}}
{{character}}
{{radical}}
{{strokeCount}}
{{zhuyin}}
{{wordCandidates}}
{{image}}
```

若採純文字 `{{...}}`，解析器必須能處理 Word 把標記拆成多個 run 的情況；更穩定的做法是以內容控制項 tag 作為語意識別，文字僅供設計者在 Word 中辨識。

## 六、交付前檢查清單

- [ ] 檔案是 `.docx`，可在 Word 正常開啟。
- [ ] `word/document.xml` 的本文直接段落至少 63 個。
- [ ] 索引 `0`、`1`、`2`、`3`～`7`、`32` 的用途沒有變動。
- [ ] 第一題母版在索引 `2`，而且所有必要的生字位置都是單一 `<w:t>看</w:t>`。
- [ ] 部首位置是單一 `<w:t>目</w:t>`。
- [ ] 筆畫位置是單一 `<w:t>9</w:t>`。
- [ ] `第 1 題` 完整位於同一個 `<w:t>`。
- [ ] 語詞標題在索引 `7`，並預留程式附加文字的空間。
- [ ] 索引 `32` 仍是手動分頁段落。
- [ ] 注音位置使用支援現行 IVS 的字型，並已在目標電腦測試。
- [ ] 未放置或期待以檔名／替代文字辨識的圖片佔位符。
- [ ] 已用至少 6 個生字測試，確認跨頁後版面與分頁正常。
- [ ] 已用有圖片與無圖片兩種資料測試固定圖片座標。
- [ ] 已解壓成品，確認文字替換結果、relationship 及 `word/media/` 內容。
